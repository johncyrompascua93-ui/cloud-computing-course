# Reflection Paper: Everyday Cloud Concepts & Version Control

Cloud computing powers many of the everyday digital applications we rely on. Three cloud services I regularly use are Google Drive, Netflix, and Canva. 

Google Drive is a Software as a Service (SaaS) delivered over a public cloud deployment model. It provides end-users with direct storage access without requiring them to manage underlying servers. Netflix operates as SaaS on a public cloud infrastructure (primarily AWS), delivering streaming content globally to millions of concurrent users. Canva is also a SaaS application hosted on a public cloud, giving users web-based graphic design tools without requiring local software installation. All three applications rely on public cloud infrastructure to ensure scalability, automatic updates, and multi-device access.

Version control systems like Git and GitHub are critical when managing cloud infrastructure, particularly in modern DevOps and Infrastructure as Code (IaC) workflows. Cloud environments consist of configuration files, scripts, and deployment templates. Without version control, tracking changes across complex configurations becomes difficult and error-prone. 

GitHub acts as a centralized platform that enables engineering teams to collaborate seamlessly. Developers can use branches to test configuration updates independently without breaking live environments. Pull requests allow peer reviews before changes are merged into production, reducing misconfiguration risks. Furthermore, Git maintains a complete revision history, making it simple to rollback to a stable state if a deployment bug occurs. Through version control, cloud projects maintain high accountability, traceability, and operational reliability.
